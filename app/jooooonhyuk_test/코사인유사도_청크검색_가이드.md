# 문서 id + 쿼리 문자열 → 코사인 유사도 상위 5개 청크 검색

## 1. 재사용할 기존 인터페이스

### 임베딩 생성 — `LLMProvider.embed()`
[app/llm/base.py:37](../llm/base.py#L37)

```python
async def embed(self, text: str) -> list[float]: ...
```

추상 인터페이스이고, 실제 구현체는 [app/llm/openai_provider.py:62](../llm/openai_provider.py#L62)의 `OpenAIProvider.embed()`입니다.
OpenAI `text-embedding-3-small` 모델로 1024차원 벡터를 반환합니다
(`app/core/config.py`의 `embedding_model`, `embedding_dim` 설정 사용).

"문자열 넣으면 벡터 나온다"는 것만 알면 되고, 내부 프로바이더 구현은 신경 쓸 필요 없습니다 (어댑터 패턴).

### 코사인 유사도 검색 — `ChunkRepository.dense_search()`
[app/db/repositories/chunk_repository.py:79-99](../db/repositories/chunk_repository.py#L79-L99)

```python
async def dense_search(
    self,
    bid_notice_id: int,
    query_embedding: list[float],
    limit: int = 10,
    l_topics: list[str] | None = None,
) -> list[tuple[Chunk, float]]:
    distance = Chunk.embedding.cosine_distance(query_embedding).label("distance")
    stmt = (
        select(Chunk, distance)
        .where(Chunk.bid_notice_id == bid_notice_id, Chunk.embedding.is_not(None))
    )
    ...
    result = await self.session.exec(stmt.order_by(distance).limit(limit))
    return [(row[0], row[1]) for row in result.all()]
```

정확히 원하는 기능입니다:

- 문서 id(`bid_notice_id`)로 필터링
- `Chunk.embedding.cosine_distance(query_embedding)`으로 pgvector의 `<=>` 연산자를 SQLAlchemy 레벨에서 사용
- 거리 오름차순 정렬(가까울수록 유사) 후 `limit`개만 반환

- `Chunk` 모델: [app/db/models/bid.py:61-94](../db/models/bid.py#L61-L94), `embedding` 컬럼은 `pgvector.sqlalchemy.Vector(1024)` 타입
- 참고: 하이브리드 검색 [app/rag/retrievers/hybrid_search.py:28-55](../rag/retrievers/hybrid_search.py#L28-L55)의 `hybrid_search_chunks()`가 `llm.embed()` → `dense_search()` + `sparse_search()` → RRF 병합 흐름을 보여줍니다. 순수 코사인 유사도만 필요하면 sparse는 빼고 dense만 쓰면 됩니다.

### DB 세션 — `get_session`
[app/db/session.py:22-29](../db/session.py#L22-L29)에 정의된 FastAPI dependency.
라우터에서는 `Depends(get_session)` 또는 `SessionDep`([app/api/deps.py:27](../api/deps.py#L27))으로 주입받습니다.

## 2. 단계별 구현 순서

**1단계 — 입력 받기**
FastAPI 라우터라면 path/query param으로 `bid_notice_id: int`, `query: str`을 받습니다.
스크립트/테스트 용도라면 `input()`으로 받아도 됩니다.

**2단계 — 쿼리 문자열 임베딩**

```python
query_embedding = await llm.embed(query)
```

`llm`은 `LLMProvider` 인터페이스를 만족하는 인스턴스(보통 `OpenAIProvider()`)입니다.
`app/llm/`의 provider 레지스트리를 통해 얻는 방식을 그대로 따르세요(fallback 로직이 있다면 그것까지 재사용).

**3단계 — DB 세션 얻고 리포지토리 생성**

```python
async with async_session_factory() as session:
    chunk_repo = ChunkRepository(session)
```

**4단계 — dense_search 호출**

```python
results = await chunk_repo.dense_search(
    bid_notice_id=bid_notice_id,
    query_embedding=query_embedding,
    limit=5,
)
```

반환값은 `list[tuple[Chunk, float]]` — `(청크 객체, 코사인 거리)` 튜플입니다.
**거리이지 유사도 점수가 아니라는 점 주의** (0에 가까울수록 유사, `1 - distance`로 유사도 스코어를 뽑고 싶으면 직접 변환).

**5단계 — 결과 가공/출력**

```python
for chunk, distance in results:
    print(f"[{chunk.chunk_index}] score={1 - distance:.4f}\n{chunk.content[:200]}")
```

## 3. 전체 조합 예시

```python
from app.llm.openai_provider import OpenAIProvider
from app.db.session import async_session_factory
from app.db.repositories.chunk_repository import ChunkRepository

async def search_top5(bid_notice_id: int, query: str):
    llm = OpenAIProvider()
    query_embedding = await llm.embed(query)

    async with async_session_factory() as session:
        chunk_repo = ChunkRepository(session)
        results = await chunk_repo.dense_search(
            bid_notice_id=bid_notice_id,
            query_embedding=query_embedding,
            limit=5,
        )

    return results
```

## 4. 배우면 좋은 포인트

- **직접 코사인 유사도를 계산하지 마세요.** numpy로 벡터 뽑아서 내적 계산하는 식으로 짜고 싶은 유혹이 있을 수 있는데, pgvector가 인덱스(HNSW/IVFFlat 등)로 DB 레벨에서 처리해주므로 `Column.cosine_distance()`를 그대로 쓰는 게 훨씬 효율적입니다. 매번 전체 청크를 파이썬으로 로드해서 비교하면 문서가 커질수록 느려집니다.
- **`bid_notice_id` 필터가 WHERE절에 있다는 점**이 중요합니다. 이게 없으면 전체 DB의 모든 문서 청크와 비교하게 되어 느리고 결과도 엉뚱해집니다.
- **테스트할 때는 실제 DB 대신 Fake 클래스를 씁니다.** `tests/unit/test_evaluation_criteria_fallback.py`처럼 `FakeChunkRepository`에 `dense_search` 메서드를 duck-typing으로 구현해서 넣으면 DB 없이 로직 검증이 가능합니다.
