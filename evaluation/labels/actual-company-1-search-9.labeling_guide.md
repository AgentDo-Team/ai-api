# 실제 회사 프로젝트 기반 청크 라벨링 가이드

## 목적

이 문서는 `actual-company-1-search-9.prelabels.csv`의 자동 초안 라벨을 사람이 검수해 검색 평가용 정답 데이터로 확정하기 위한 기준이다.

자동 라벨은 회사 역량과 성공 프로젝트에 등장하는 기술·도메인 표현을 기준으로 만든 검토 보조값이다. 검색 순위는 자동 관련도 등급 계산에 사용하지 않았다. 이미 검색된 순위로 정답을 만들면 현재 검색기의 판단을 정답으로 재사용하는 순환 평가가 되기 때문이다.

## 검수할 열

- `auto_chunk_relevance`: 규칙 기반 자동 초안 등급. 직접 수정하지 않는다.
- `auto_confidence`: 초안의 확신도. 사람이 판단할 때 참고만 한다.
- `auto_matched_terms`: 초안 판정에 사용된 회사 역량·프로젝트 관련 표현이다.
- `auto_reason`: 자동 판정 근거다.
- `review_priority`: 검수 순서다. `P0`부터 확인하고 그다음 `P1`, `P2` 순으로 진행한다.
- `review_reason`: 해당 행이 우선 검수 대상으로 지정된 이유다.
- `final_chunk_relevance`: 사람이 확정한 최종 등급을 입력한다.
- `reviewer_notes`: 판단이 애매하거나 등급을 수정한 이유를 짧게 기록한다.

## 최종 관련도 판정 기준

### 3점: 직접적인 핵심 적합

회사의 역량이나 성공 프로젝트를 공고의 핵심 업무에 바로 적용할 수 있는 청크다.

- RAG, 생성형 AI, LLM, 자연어 처리, 질의응답, 챗봇
- 민원 자동응답, 검색 증강, 임베딩·벡터 검색
- 회사가 수행한 기능과 사실상 같은 핵심 요구사항

단순히 기술명이 한 번 등장했다는 이유만으로 3점을 주지 않는다. 그 기술이 실제 구축 대상이나 주요 기능으로 요구되어야 한다.

### 2점: 구체적인 연관 또는 전이 가능한 적합

핵심 AI 기능과 완전히 같지는 않지만, 회사의 구축 경험을 실질적으로 활용할 수 있는 청크다.

- 공공 정보시스템 또는 통합정보시스템 구축
- 데이터·시스템 연계와 통합
- 대시보드, 데이터 활용 체계, API 연계
- Python, FastAPI, PostgreSQL, pgvector 등 보유 기술과 구체적으로 맞는 구현 요구사항

기술이나 기능의 연결 근거가 문장에 명확해야 한다. 공고 전체가 관련 있다는 이유만으로 모든 하위 요구사항에 2점을 주지 않는다.

### 1점: 일반적인 SI 수준의 부분 적합

회사가 수행할 가능성은 있지만 현재 회사 프로필만으로 차별화된 적합성을 설명하기 어려운 청크다.

- 일반적인 정보시스템 구축·개선
- 데이터베이스, 웹 서비스, 응용프로그램, 인터페이스 같은 포괄적 표현
- 프로젝트 관리, 운영 또는 개발의 일반 요구사항

### 0점: 관련 없음

회사의 역량·실적과의 연결 근거가 없거나, 검색 결과로 추천할 가치가 거의 없는 청크다.

- 납품, 교육, 보고, 계약, 행정 절차만 설명하는 문장
- 일반 보안·품질·테스트 조항만 있고 회사 고유 역량과 연결되지 않는 문장
- 표의 제목이나 목차처럼 맥락이 부족한 청크
- 검색어가 우연히 포함됐지만 의미상 다른 내용

## 권장 검수 순서

1. `review_priority=P0` 244개를 먼저 모두 확인한다.
2. `P1` 322개를 확인한다. 시간이 부족하면 `auto_confidence=low`와 1·2점 경계 사례를 우선한다.
3. `P2` 237개는 먼저 10% 이상 표본 검수한다. 공식 골드셋으로 사용할 때는 결국 803개 전부에 최종 등급을 입력한다.
4. 자동 초안과 다르게 판단했다면 `reviewer_notes`에 핵심 이유를 남긴다.
5. 검수가 끝난 뒤 `final_chunk_relevance`의 빈칸, 0~3 이외 값, 중복 `chunk_id`를 검사한다.

## 주의 사항

- `dense_rank`, `bm25_rank`, `rrf_rank`, `retrieved_by`는 관련도 판정 근거로 사용하지 않는다. 이 값들은 놓치면 성능 지표에 영향이 큰 행을 먼저 검수하기 위한 우선순위 정보다.
- 공고 관련도인 `notice_relevance`와 청크 관련도는 별개다. 공고가 3점이어도 행정·보안·테스트 청크는 0점일 수 있다.
- 현재 803개는 기존 검색 방식들이 수집한 후보 풀이다. 이 데이터로 MRR·nDCG와 상위 결과 품질은 평가할 수 있지만, 전체 문서에서 놓친 관련 청크까지 포함한 엄밀한 Recall을 계산하기에는 부족하다.
- 최종 Recall 평가를 하려면 대상 공고의 `개요`·`요구사항` 전체 청크를 별도로 내보내 같은 기준으로 라벨링해야 한다.
- 자동 초안만 채워진 파일은 공식 정답 데이터가 아니다. 사람의 `final_chunk_relevance` 검수가 완료된 뒤 평가 입력으로 변환한다.
